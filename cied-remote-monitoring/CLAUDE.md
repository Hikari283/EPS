# 開発時のルール

このプロジェクトは患者の個人情報（要配慮個人情報）を扱う医療システムです。

## 🔰 このプロジェクトを初めて開いたClaudeへ

**会話履歴はPCごとに独立しているため、過去のやりとりは参照できません。
必要なことはすべて以下のファイルに書いてあります。作業を始める前に順に読んでください。**

1. **[docs/06-roadmap.md](docs/06-roadmap.md) の「6.1 次にやること」** ← まずここ。
   現在地・決定事項・次のアクションが1か所にまとまっている
2. [README.md](README.md) — プロジェクトの概要と、設計上の重要な判断
3. このファイルの残り（守るべきルール）
4. 該当する作業の設計章（[docs/](docs/) の 01〜05）

`mockups/ui-mockup.html` をブラウザで開くと、合意済みの画面イメージが確認できる。

### ユーザーについて

医療機関の職員で、エンジニアではない。CIEDの遠隔モニタリング業務の担当者。
臨床側の判断（項目の妥当性、変化しきい値など）はユーザーが持っている。
技術的な判断はこちらで出し、**臨床的な妥当性は必ず確認を取ること。**

### 進め方の約束

- 設計判断を変えたら、**必ず該当ドキュメントも更新する**。
  次に別のPCで開いたときに、ドキュメントだけが唯一の引き継ぎ資料になる
- 推測で埋めた箇所は「★仮の値」「要確認」と明示する。断定しない

## 絶対に守ること

1. **実患者データを外部に送信しない。** Claude Code とのやり取りを含む。
   帳票の内容を相談する場合は、氏名・ID・生年月日・住所・電話番号をすべて除去してから。
2. **`samples/` 配下は絶対にコミットしない。** `.gitignore` で除外済み。
3. **外部ネットワークへ通信するコードを書かない。** OCRモデル・辞書・JSライブラリはすべて同梱する。
   `requests` / `httpx` / `urllib` を業務コードに入れない。
   モデル自動ダウンロード機能を持つライブラリは、必ずローカルパス指定に固定する。
4. **抽出値を自動確定しない。** 必ず人が確認する導線を残す。
5. 抽出できなかった項目は、推測で埋めずに `null` を返す。
6. **患者IDは8桁の数字で、先頭ゼロが意味を持つ（例 `00123390`）。必ず文字列として扱う。**
   `int()` に通した瞬間に別人になる。DBの型は `TEXT`、JSONも文字列、
   CSV取込はExcel経由を避ける（Excelが先頭ゼロを消す）。取込時に8桁であることを検証する。

## 設計上の約束

- `src/core/` は UI・DB・Web を一切importしない（純粋ライブラリとして保つ）
- 抽出ルールはコードに書かず `src/profiles/*.yaml` に置く
- 精度に関わる変更は、必ず評価スクリプト（`python -m cli.eval`）の数値で効果を示す

## ドキュメント

設計は [docs/](docs/) にあります。実装前に該当章を読んでください。
設計判断を変える場合は、コードだけでなくドキュメントも更新してください。

## 開発環境

- macOS と Windows の両方で作業する。実装はクロスプラットフォームを維持すること
- Windows用exeのビルドはWindows実機でのみ可能（macOSでは作れない）
