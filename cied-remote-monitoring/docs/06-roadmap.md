# 06. ロードマップ・次アクション

## 6.1 次にやること（2026/08/21 時点）

### 現在地

**動くツールができた。`carelink_extractor.html` をブラウザで開き、CareLinkレポートを
コピー&ペーストすると、項目を抽出してカルテ転記文を生成する。** Pythonのインストールは
不要（2026/08/21、ユーザーの決定でPythonを使わない方針に転換。[02.0](02-architecture.md#20-方針転換20260821-単体html--javascriptpythonは使わない)）。

抽出ルールはMedtronicの実レポート3ページ分の実データで検証済み
（`tests/test_extract_engine.py` のPython版で先に検証し、同じロジックをJSに移植。
`carelink_extractor.html` 自体もヘッドレスブラウザで動作確認済み）。

対応済みの項目: 機種名／型番／シリアル番号／植込み日／モード／基本レート／上限トラッキング／
予測寿命（推定・最小・最大）／電池電圧／RRT電圧／RA・RVのリードインピーダンス／
RA・RVのペーシング閾値／P波・R波高値／AS-VS・AS-VP・AP-VS・AP-VP（直近期間）／VT件数。

**次にやること:**

1. **実際にツールを使ってみる。** `cied_app.html`（本体）で実レポートを何件か試し、
   誤って抽出される項目・見た目のおかしい所があれば教える
2. カルテ転記文のテンプレート（`○デバイス種類`の行など）が実際の書き方と合っているか確認する
3. 台帳へインポートした行（元Excelにpatient_id/氏名が無かったため仮ID `9000001〜` を採番）に、
   実際の患者ID・氏名を入力していく
4. 他メーカー（Abbott/Boston Scientific/MicroPort/WCD）は台帳登録のみ対応（自動抽出は対象外、
   [01.要件定義](01-requirements.md#対象メーカー--システム)）。もし将来メーカーを増やす場合も
   同じHTML+JS方式で追加できる

`python -m cli.list_labels` やオフラインPCへのPython持ち込み手順（`docs/08-offline-setup.md`）、
Python版の抽出エンジン（`src/core/extract/`）は実装・検証済みだが、**Pythonを使わない方針に
転換したため、当面は参照実装として残すのみで使わない。**
数件程度のレポートを見るだけなら、今回のようにコピー&ペーストで十分。

### 台帳の初期データ投入・外来準備シートの実データ連携（2026/08/21）

- ユーザーの既存Excel台帳（ハイパワー／PMDシート）を、氏名・IDを除いた項目名・書式の確認のみに使い、
  台帳インポート用CSVを作成した（実データそのものはリポジトリに含めない。ローカルでのみ受け渡し）。
  **元Excelの「抜去」シートに未匿名化の患者氏名・IDが残っていた事故があった**（ユーザーへの報告後、
  そのシートを除いたファイルに差し替えてもらい対応）。以後、アップロードされたExcel/CSVは
  必ず先に列を軽く検査し、氏名・ID列が本当に空か確認してから処理する運用にする
- `cied_app.html` の「①レポート取り込み」で確定した内容は、患者IDをキーに台帳を自動更新する
  （台帳固有項目は上書きしない。動作確認済み）
- 「③外来準備シート」を、単なる患者一覧から**直近レポートのリード値（RA/RV インピーダンス・
  波高値・閾値・電池電圧・予測寿命）を並べて表示する確認シート**に作り替えた
  （ユーザー提供の実際の外来準備Excelを参考に設計。動作確認済み）
- スマホでタブ（③外来準備シート等）が画面からはみ出してタップできない不具合を修正
  （狭い画面では均等幅で縮小・折り返す。iPhone SE〜Pixel 5相当のサイズで確認済み）
- **同じ患者のレポートを複数回に分けて確定した場合の項目統合ロジックを修正。**
  当初は「一番新しいレポート1件」の項目だけを見ていたため、例えば「電池情報」だけの用紙を
  確定すると、そこに無い閾値等の項目が、以前の確定分に値があっても空欄に戻ってしまっていた。
  項目ごとに独立して「一番新しく値が入っていた記録」を探す方式（`mergedReportFieldsFor`）に変更し、
  部分的な取り込みを繰り返しても既存の値が消えないようにした。動作確認済み
- **レポート取り込みが台帳の氏名・機種名等を書き換えてしまう不具合を修正。**
  患者IDが8桁でなくても確認ダイアログで素通りできてしまい、ID抽出に失敗した別々のレポートが
  同じ空欄ID（または誤入力ID）の台帳行に重なって、氏名が書き換わり続ける事故が起きていた。
  - 患者IDが8桁ちょうどでない場合は保存自体をブロックする（確認ダイアログでの素通りを廃止）
  - CSV取込でも、空欄IDを`0000000`等に丸める処理をやめ、8桁でない行はスキップして件数を報告する
  - 既存デバイスへのレポート確定では、**氏名・ID・種別・メーカー・機種・シリアル・植込み日・MRIを
    一切変更しない**（更新するのは遠隔状況・最終フォロー日のみ）。これらは②デバイス台帳の
    編集フォームからのみ変更する
  - 既存デバイスの氏名と、確定しようとしている氏名が食い違う場合は確認ダイアログを出す
    （ID入力ミスの早期発見）
  動作確認済み（ヘッドレスブラウザで: 不正ID時に保存されないこと／手動修正した氏名・機種名が
  再確定後も残ること／氏名不一致時に警告が出ることを確認）

### 使い勝手の改善（2026/08/21）

- **患者IDが8桁でないとき、赤枠＋警告文で常に分かるようにした**（①レポート取り込み画面、
  ②デバイス台帳の編集フォームの両方）。空欄（＝抽出できなかった）のときも警告するよう変更
- **貼り付け(Ctrl+V)したら自動で抽出が走るようにした。** 「抽出する」ボタンを押す手間を省いた
- **「クリップボードから読み込む」ボタンを追加。** PDFビューアでCtrl+A→Ctrl+Cした後、
  テキストエリアに貼り付ける操作すら不要になった（`navigator.clipboard.readText()`。
  file://で開いた場合でも動作確認済み）。
  なお「PDFファイルをドロップしたら自動で読み取る」（PDFのバイナリを直接解析する）は、
  pdf.js等のライブラリが必要でこのセッションからは取得できず**実装していない**。
  ユーザーの実際の要望は「コピー後の一手間を減らす」ことだったため、上記2点で対応した
- **②デバイス台帳に削除機能を追加。** 確認ダイアログ付き。削除すると、その患者に紐づく
  取り込み済みレポートも一緒に削除される
- **③外来準備シートの数値欄を編集可能にした。** 自動抽出・自動反映された値を手直しできる。
  「Dr Call」「当日メモ」の自由記入欄も追加（実際の外来確認Excelにあった記入欄を再現）。
  これらの編集はその場限りで、保存はされない（「読み込む」を再度押すとリセットされる）
  設計をREADME/このファイルに明記

決まったこと:

| 項目 | 決定 |
|---|---|
| レポートの取得 | 各社システムから**PDFで直接取得できる**。印刷→スキャンは廃止 |
| ネットワーク | インターネット系と電子カルテ系は分離。**院内専用USB**で運ぶ |
| Phase 1 の形 | **本人1人での単独運用**（自分のPC 1台、localhost、認証なし） |
| 患者ID | **8桁の数字、先頭ゼロあり**（2026/08/21修正: 当初7桁としていたが誤り）。必ず文字列として扱う |
| システムの性格 | 遠隔モニタリング支援 **＋ 院内CIEDの台帳** |
| 主な画面 | 取り込み／確認・修正／カルテ転記／デバイス台帳／外来準備シート |

**当初の最大リスク（スキャン品質によるOCR精度不足）は解消している。**

### A. 現場で確認するだけのこと（コスト小・効果大）

**A-1. 各社PDFのテキストレイヤーの有無** ← 最優先

②`Ctrl+F` で画面に見えている単語がヒットするか。両方できればテキストPDF。

| メーカー | PDF保存 | テキストレイヤー |
|---|---|---|
| Medtronic (CareLink) | ○ | **○ 確認済み**（コピー&ペーストで文字が取れた。2026/08/21） |
| Abbott (Merlin.net) | ○ | 未確認 |
| Boston Scientific (LATITUDE) | ○ | 未確認 |
| MicroPort | ○ | 未確認 |
| WCD (ZOLL LifeVest) | ○ | 未確認 |

全社テキストPDFなら、OCRは当面書かなくてよい。
画像PDFだったメーカーについてのみ、OCR経路を作り込む。

**A-2. カルテからコピーした「患者ID一覧」の実物**

外来準備シートの読み取りルールを実態に合わせるため。
見出し行・時刻・列の並びが分かればよい。
**患者IDと氏名はダミーに置き換えて**、形式だけ分かる状態で共有する。

**A-3. 既存の台帳（Excel等）があるか**

あれば、その列構成に合わせてCSV取込を作る。無ければ初期投入の方法を別途考える。
⚠️ Excelを経由すると患者IDの先頭ゼロが消える点に注意
（[01. FR-6](01-requirements.md#患者idの形式確定)）。

**A-4. レポートPDFを1〜3件ずつ手元に用意**

外部に渡す必要はない。自分のPC内で処理が完結する。

### E. 実装に入る条件と、最初の一歩

**A-1 と A-4 が揃えば M1 に着手できる。** B は並行して進めればよい。

#### 手順: ラベル一覧の取得（★方針転換: 手作業でよい）

1件〜数件のPDFから項目名を洗い出すだけなら、Pythonのセットアップは不要。
**PDFビューアで開いて全選択・コピーし、メモ帳やExcelに貼り付けるだけで十分**
（テキストPDFなので選択・コピーがそのまま使える。[3.2](03-extraction-design.md#32-a-テキストレイヤー優先重要)）。

1. 各社システムからレポートPDFを保存する（メーカーごとに1〜3件）← **未着手（A-4）**
2. テキストレイヤーの有無を確認する（A-1）← 上記のコピー操作ができれば、それ自体が確認になる
3. PDFビューアで全選択→コピー→メモ帳に貼り付け、項目名らしき行を目視でリストアップする
4. その一覧に患者の識別情報が混ざっていないか確かめる
5. その一覧をもとにプロファイルYAML（[04.4](04-data-model.md#44-表記ゆれの管理)）を作る ← 未着手

抽出ルールの作成に必要なのは帳票の**項目名**であって、患者の値ではない。
項目名は個人情報ではないため、そのまま扱える。**PDF本体を外部に出す必要はない。**

#### `cli.list_labels` スクリプトについて（実装済み・今は使わなくてよい）

`python -m cli.list_labels` を先に実装したが、これは**何十件ものPDFを一括処理する**
ような場面（M2以降、実運用に近づいてから）で効いてくるもの。
今のように数件を目視確認する段階では、上記の手作業のほうが速く、
Python環境の用意（オフラインPCへの持ち込み含む）というリスクも避けられる。
コードと `docs/08-offline-setup.md`（持ち込み手順）は残してあるが、**M2でバッチ処理が
必要になるまで着手を保留する。**

| Windows実機ビルドで詰まる | 中 | M2の早い段階でHello World相当のexeを1本通しておく |
| 台帳の初期データ投入が重すぎて頓挫する | 中 | CSV取込を先に作る。既存Excelの有無を早めに確認（A-3） |
| 開発が属人化して継続できなくなる | 中 | ドキュメントとテストを維持。プロファイルYAMLは非エンジニアでも読める形式にしてある |
| 商用製品のほうが早くて安いと後で判明する | 中 | M3の効果測定で正直に比較する。撤退も選択肢に残す |

## 6.4 判断のチェックポイント

無闇に進めず、以下で立ち止まって判断する。

1. **M1完了時**: 抽出は実用に足るか。足りなければ方針変更 or 中止
2. **M3完了時**: 転記時間は実際に短縮されたか。商用製品と比べて優位はあるか
3. **M4着手前**: 院内サーバーを立てる承認が得られるか
